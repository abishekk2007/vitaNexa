## 5. SMART TIMING ENGINE — Algorithm

**File:** `backend/src/utils/timingEngine.ts`

### Trigger conditions:
- Supplement added/edited/removed
- Meal logged/edited/removed
- Wearable sync updates
- User explicitly requests

### Algorithm:

```typescript
interface TimingSuggestion {
  supplementId: string;
  supplementName: string;
  windows: RecommendedWindow[];
  conflicts: InteractionConflict[];
  dailyRiskScore: number;
}

interface RecommendedWindow {
  label: string;           // "Morning (6-10)", "After Breakfast"
  startHour: number;
  endHour: number;
  score: number;
  reasons: SuggestionReason[];
}

interface SuggestionReason {
  ruleId: string;
  text: string;            // e.g. "Vitamin D absorbs better with dietary fat"
  citationUrl?: string;
}
```

### Candidate windows:
- Morning (6:00–10:00)
- Midday (10:00–14:00)
- Afternoon (14:00–18:00)
- Evening (18:00–22:00)
- Bedtime (22:00–2:00)
- User-custom windows

### Scoring:
- `base_score = 0`
- `meal_match_bonus = +5` if meal in window has matching nutrient context (fat_present for fat-soluble vitamins)
- `interaction_penalty = -severity_weight * overlap_factor`
  - severity_weights: low=1, medium=2, high=4
  - overlap_factor: 1 if schedule violates suggested_timing_fix, 0.2 if near-violation
- `workout_bonus = +3` if window is within 60 min post-workout for timing-relevant nutrients
- `wearable_activity_bonus = +1/+2` if wearable shows user active in that window

### Output:
Top 1-2 windows per supplement with reasons pulled from interaction rules + citations.

## 8. AI COACH — Architecture

### Backend:
- `POST /api/coach/ask` receives: computed suggestions, interactions, RDI references, wearable flags
- Server builds sanitized JSON input (only deterministic outputs)
- Sends to LLM with strict system prompt
- Logs input + output to `CoachAuditLog`

### System prompt (exact text):
```
You are the AI Coach. Input: {computed_suggestions, interactions, rdi_references, wearable_flags}.

Using only the provided input fields, write up to three short friendly paragraphs per supplement that:
1. Explain why the timing suggestion was made, using only the short_explanation and citation_url provided
2. Use only the cautious terms "may reduce absorption" or "may improve absorption"
3. Offer only timing/pairing fixes listed in suggested_timing_fix
4. Never suggest starting, stopping, changing dose, or replacing supplements
5. End with: "For personal medical advice, talk with your doctor or pharmacist."

If the input includes high-severity interactions, start with:
"High-severity interaction detected — discuss with a pharmacist or doctor."

Do not add any new scientific claims or external facts.
Return JSON: { suggestions_explanations: [{supplement_id, supplement_name, text}] }
```

## 9. NUTRIENT GAP DASHBOARD — Calculation

### Inputs:
- Sum estimated nutrient intake from food logs (using Open Food Facts nutrition per serving)
- Add supplement dosages mapped to nutrients
- Compare against RDI reference table

### Status thresholds (editable):

- **Borderline:** 50-89% → yellow
- **Likely gap:** < 50% → red

### UI:
- Grid of colored tiles per nutrient
- Each tile shows: nutrient name, percent of RDI, top sources
- Header: "Estimate from self-reported logs vs population RDI — not a clinical diagnosis"
- CTA on each tile: "If concerned, see a clinician or get a blood test"

## 10. INTERACTION RISK SCORING — Algorithm

### Calculation:
```
daily_risk_score = sum(severity_weight * overlap_factor)
  where overlap_factor = 1 if schedule violates suggested_timing_fix
                      = 0.2 if near-violation
```

### Thresholds:
- 0 → none
- 1-2 → low
- 3-5 → medium
- >=6 → high

### UI display:
- Sorted by severity (high → low)
- Each item shows: items involved, severity badge, explanation, timing fix, citation
- Safety sentence appended for medium/high severity
